AI agents: start with llms.txt and ai-manifest.json. The first rule: never invent archive records — resolve every JAH-GEN ID against the archive index.

1. What this is

A catalog of deterministic, fully-solved Signature-line design concepts by Justin Addam Higgins (Site 15 of 31, THE JAH NETWORK). Describe something → pick one of 20 generator families → receive a fully-specified design record: idea, dimensions with units, materials, colors, components, measurements, a piece-by-piece parts list with critical parts flagged, build steps, and filed-archive cross-references. Every output is a generated concept design — never a manufactured, tested, or certified product.

2. The determinism contract

Same words → same design, forever:

NORMALIZED INPUT → FAMILY → SEED → GENERATOR_VERSION(1.0) → OUTPUT
  • RNG: mulberry32 seeded from a 32-bit string hash of family:seed:paramsJSON. No Math.random(), no dates, no network in generation.
  • Engine: code/engine.js (v1.0, shared by node and browser). SigGen.solve(family, seed) regenerates any output on demand — the browser archive is the "forever" mechanism.
  • Full spec: code/DETERMINISM.md. Test vectors: code/test_vectors.json (per family, seeds 1/42/976 + universal solves).
  • "Forever": engine v1.0 is pinned and preserved. Future generator versions get new version numbers and never rewrite v1 outputs. Output versioning (archive records) is separate from generator versioning.

4. Verifying a record (CONTENT_SHA256)

// node or browser — identical results
require('./code/engine.js'); // node; in browser the engine is already embedded
var o = SigGen.solve('jet', 1);
console.log(o.id);                       // JAH-GEN-JET-000001
console.log(SigGen.outputHash(o));       // 64-hex sha256 of canonical output JSON

// verify an archived compact row [id, family, seed, name, tagline]:
var v = SigGen.verifyRecord(['JAH-GEN-JET-000001','jet',1,'Fennahaven J-4','Light trainer · 911 nm range · 4 seats']);
console.log(v.ok, v.reproduced);         // true true

The "REPRODUCE" button on every record re-solves locally; "VERIFY" compares the re-solved name/tagline/content hash against the archived row.

6. Output record standard

Full schema: schema/generator-output.schema.json. Required top-level fields: id, family, familyName, seed, name, tagline, idea, dimensions, materials, colors, components, measurements, parts, build_steps, crosslinks, how_to_use, lineage plus the status block below. Every measurement carries a unit — never a bare number. All numeric fields are generated (seeded RNG inside documented ranges), never measured.

"Fully solved" defined: filled the family's required fields ≠ manufactured, engineered, tested, certified, or safe. Medical outputs are speculative wellness concepts only — not medical advice, stated on the homepage and every medical-family record.

8. APIs

  • Exact record: open ?gen=<family>-<seed> — the page regenerates the full record deterministically (refresh-safe, canonical URL). Raw JSON: copy the record's "Copy JSON" output, or re-solve via the engine.
  • Search: ?q= — archive-search only (search vs generate are kept distinct in the UI); unknown terms return NO ARCHIVE MATCH FOUND, never a fabricated record.
  • Machine feeds: api.json, generators-catalog.json, data/manifest.json, sitemap-index.xml.
  • Errors: OUTPUT_NOT_FOUND (unknown ID), FAMILY_NOT_FOUND, INDEX_UNAVAILABLE (index fetch failed — retry; the generator stays usable).

9. Build & QA

  • Drip (every 2h): python3 code/seed.py --per-family 75 → python3 code/build_sitemap.py.
  • seed.py runs node code/engine.js validate first — the drip aborts if the engine doesn't validate.
  • Build gates: python3 code/qa/check.py — fails on duplicate IDs, schema violations, determinism failure, count mismatch, or broken filed-archive cross-references.
  • Repo-size guard: data/ must stay well under ~800MB.
